# pangu-memory

**给 LLM 应用插一块可插拔、可解释、可遗忘的本地长时记忆。**

不是「查资料」，是「记住你」。一个 sqlite 文件，零依赖，零服务。

```python
from pangu import Memory

m = Memory()                      # ~/.pangu/db.sqlite
m.write("我九月从深圳搬到北京")
m.write("我住昌平")

print(m.context_for("她现在住哪"))
# 关于用户的长期记忆（按可信度排序）：
# - 我住昌平
# 以上记忆若与用户当前说法冲突，以用户当前说法为准。
```

---

## 为什么要做这个

做 AI 助手、陪伴、客服的人，迟早都要回答同一个问题：**这个用户是谁，他上次说过什么。**

现在的答案基本都是：把历史对话切块 → embedding → 向量库 → top-k 塞回 prompt。

这条路能跑，但它解决的是**检索**，不是**记忆**。区别在这四件事上：

| 知识库要解决 | 记忆层要解决 |
|---|---|
| 文档切分、召回率 | 什么值得记、记多久、什么时候该忘 |
| 静态内容 | 会过时、会互相矛盾的事实 |
| 一次问答 | 跨会话、跨月的连续性 |
| 召回准不准 | **为什么召回它**，以及两条冲突信息谁算数 |

第三行那句「谁算数」，就是市面上开源方案集体缺失的地方。它们会同时把「她住深圳」和「她住昌平」塞进你的 prompt，然后指望模型自己猜。

这个库不猜。**它记住时间，并且解释自己。**

---

## 它到底做了什么

### 1. 不是所有差异都是矛盾

`我喜欢咖啡` 和 `我喜欢茶` 共存。只有**函数型谓词**（`live_at`、`age`、`partner`……）在一个时刻只能有一个值。

```python
m.write("我喜欢咖啡")
m.write("我喜欢茶")     # 两条都在，谁也没取代谁
```

### 2. 时间把矛盾变成演变

`我小时候住福田` 和 `我住昌平` 不冲突——前者被存成**闭区间**（有开始也有结束），它永远不会跟「现在住哪」抢。

```python
m.write("我小时候住福田")
m.write("我住昌平")
m.recall("她现在住哪")   # → 只有昌平
m.recall("她小时候住哪")  # → 福田（标记为已失效）
```

### 3. 什么都不删

被取代的事实保留原区间和一条 `superseded_by` 指针，随时可查：

```python
m.write("我住深圳")
m.write("我住昌平")

for r in m.history(predicate="live_at"):
    print(r.object, "→", r.t_valid_to, "被", r.superseded_by, "取代")
# 深圳 → 2026-10-22T15:41:02 被 3 取代
# 昌平 → None 被 None 取代
```

### 4. 不确定的时候，隔离而不是猜

新说法明显不可信（置信度低于旧事实一大截，或时间上自相矛盾），它会被**入库但隔离**——可审计，但不参与召回，等人来裁决。

```python
m.write("我住昌平")
m.remember("live_at", "上海", confidence=0.45)

m.recall("她现在住哪")        # → 昌平，不受干扰
len(m.conflicts())            # → 1，等人裁决
```

### 5. 每次召回都说得出理由

没有 `why` 的召回，等于把调试成本转嫁给下一个人。

```python
m.recall("她现在住哪")[0].why
# 谓词命中 live_at · 时效 2026-10-22 · 仍有效 · 最近确认 2026-10-22
```

---

## 决策表（这就是全部策略）

| 情况 | 动作 | 说明 |
|---|---|---|
| 同主体 + 同谓词 + 同值 | `duplicate` | 加强，不新增行 |
| 函数型谓词 + 新值 + 新的时间 | `supersede` | 旧区间关闭，留指针 |
| 函数型谓词 + 新值 + 置信度明显更低 | `conflict` | 隔离，不覆盖 |
| 函数型谓词 + 新值 + 时间早于现有值 | `conflict` | 疑似抽取错误，隔离 |
| 多值谓词 + 新值 | `insert` | 共存 |
| 带过去时间锚点（「小时候」「2019年」） | `insert` | 存成闭区间，不参与「当前值」竞争 |
| 撤销句（「我不再住…了」） | `retract` | 关闭旧区间，**撤销句本身不入库** |

撤销句不入库这条是刻意的：一句陈述「什么不成立」的话，被当成事实召回，是记忆系统最容易犯的错。

## 实测

不是设计目标，是跑出来的数字。

| 指标 | 目标 | 实测 |
|---|---|---|
| 召回延迟（10,003 条记忆，200 次查询） | P95 < 300 ms | **P95 54 ms** / P50 27 ms（纯 Python，单核，无向量索引） |
| 单元测试 | 全绿 | **26 个，全绿**（`python -m unittest discover -s tests`） |
| 无关记忆干扰 | 200 条无关写入后答案不变 | ✅ 有测试守着 |
| 冲突覆盖 | 取代 / 共存 / 隔离 / 撤销 / 重复 | ✅ 每条都有测试 |

```bash
python -m unittest discover -s tests -t .   # 26 tests
python bench/bench_recall.py                # 延迟基准
python examples/quickstart.py               # 端到端演示
```

## 为什么是 SQLite

因为「拷走一个文件就是全部记忆」这句话，是隐私最好的说明书。

Postgres + pgvector 更适合做服务，不适合做**一个人自己的记忆**。你这个库里存的是别人跟你说过的话，它应该能被 `cp` 走、被 `rm` 掉、被放进加密盘——而不是躺在某个容器卷里等运维来备份。

同一套 API 将来要上服务模式（FastAPI / MCP），换 `Store` 实现即可，`maintain.py` 不用改。

## API

```python
from pangu import Memory

m = Memory("~/.pangu/db.sqlite")

# 写：从自然语言里抽事实，冲突走策略
m.write("我九月从深圳搬到北京", source="chat:42")

# 写：已知结构，绕过抽取
m.remember("live_at", "昌平", confidence=0.9)

# 读：命中 + 理由
hits = m.recall("她现在住哪", limit=8)
hits[0].content, hits[0].why, hits[0].score, hits[0].stale

# 读：直接拼进 system prompt 的一段字符串（有 token 预算）
ctx = m.context_for("她现在住哪", max_tokens=600)

# 维护
m.history(predicate="live_at")   # 完整演变史
m.conflicts()                    # 待裁决
m.resolve_conflict(cid, keep="new")
m.forget(predicate="live_at")    # 显式遗忘（关闭区间，不物理删除）
m.consolidate()                  # 合并精确重复
m.audit_tail(20)                 # 最近 20 次写入/召回的理由
m.stats()
```

规则抽取只够跑通管线。要接 LLM，一行：

```python
def my_llm_extract(text, *, source="", subject="我"):
    # 调你的模型，返回 list[pangu.Fact]
    ...

m.use_extractor(my_llm_extract)
```

契约就这一个。冲突策略、存储、召回都不用动。

## 边界（写清楚，免得误会）

这个版本**故意**没做的事：

- **抽取是规则，不是模型。** 认「我住昌平」「我喜欢咖啡」这类句式，认不了复杂叙事。接 LLM 抽取器是设计内的下一步。
- **召回是字面 + 谓词，没有向量。** 所以问「她住在哪儿」能中，问「她的居住情况如何」可能中不了。54 ms 的延迟就是没有向量的代价换来的；加向量是 `Recall` 层的事，不影响 `Maintain`。
- **只服务单主体视角。** `self` 之外的 subject 能存能查，但抽取器默认第一人称。
- **中文谓词表是硬编码的。** 换语言要换表，这是 v0.1 的诚实边界。

反过来，它**已经**解决的问题：冲突消解、时间区间、隔离队列、显式遗忘、召回可解释、零依赖零服务。
